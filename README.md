# Fakt — ежедневный контент для личного бренда на проверенных фактах

Веб-приложение, которое раз в день делает ресерч по миру, Казахстану и СНГ, проверяет первоисточники и выдаёт три формата для Instagram — сторис-сторителлинг, карусель и текст рилса — с таблицей фактов и ссылок.

Стек: Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Framer Motion · Zod · Google Gen AI SDK (Gemini, Interactions API) · Tavily (поиск и извлечение страниц).

## Быстрый старт

```bash
npm install
cp .env.example .env.local        # вписать GEMINI_API_KEY и TAVILY_API_KEY
npm run dev                        # http://localhost:3000
```

Необязательный третий ключ — `GROQ_API_KEY` с [console.groq.com](https://console.groq.com). Без него всё работает, с ним раздел «Сегодня» собирается вдвое быстрее и почти не тратит суточную квоту Gemini: см. «Два провайдера» ниже.

В интерфейсе: «Бриф» → «Проверить подключение» (ключ и модель), затем «Сгенерировать выпуск». Прогон занимает 3–6 минут: в панели конвейера видно каждый поисковый запрос и каждую открытую страницу.

Нужны два бесплатных ключа: [aistudio.google.com/apikey](https://aistudio.google.com/apikey) для модели и [tavily.com](https://www.tavily.com) для поиска (карта не требуется ни там, ни там). Ключи живут только в `.env.local` и в интерфейс не попадают.

## Раздел «Сегодня» — лента дня

Главный экран. Ровно три темы на текущий день, обязательно **разных типов**, у каждой — идея и структура сторис, карусели и рилса.

| Тип | О чём |
|---|---|
| Тренд и новость | Что происходит прямо сейчас: инфоповод, изменение платформы, свежая цифра |
| Экспертное объяснение | Что полезно разобрать по существу, с опорой на данные |
| Мнение и спор | Тема с двумя защитимыми позициями — повод для обсуждения |

Три типа существуют ровно затем, чтобы день не свёлся к трём вариациям одной темы. **Тип выбирает код, а не модель:** на каждый тип берётся один материал, и взять два материала одного типа структурно невозможно.

`src/lib/feed.ts` — пять шагов, события через SSE (`/api/feed`):

1. **Повестка** — модель формулирует 9 поисковых запросов, по три на каждый тип. Идёт на лёгкую модель: у неё отдельная суточная квота.
2. **Поиск** — 9 запросов параллельно по всему вебу, без витрин соцсетей. Площадки авторских публикаций (LinkedIn, Medium, vc.ru, Reddit) **не исключаются**: споры экспертов живут там, а не в новостных лентах. Но редакционной ответственности за ними нет, и признак «издание с репутацией» им не засчитывается.
3. **Открытие** — до 12 страниц целиком и параллельно, а не по сниппетам.
4. **Отбор оснований** — пачками по 4 страницы, каждая пачка на своей модели. Модель приводит дословную цитату, **код сверяет её с текстом страницы** и отбрасывает материал, если цитаты там нет.
5. **Три формата** — по одному вызову на тему, параллельно и на разных моделях.

### Что гарантирует код, а не обещание модели

- **Цитата настоящая** — `evidenceInText` ищет её в скачанном тексте (`src/lib/text-match.ts`, общий модуль с разделом «Темы»).
- **Ссылок из воздуха нет** — при скачивании страницы адреса вырезаются вместе с разметкой, поэтому любой URL, названный моделью, был бы восстановлен по памяти. В теме хранятся только адреса страниц, которые мы открыли сами; названные на странице первоисточники показываются **без ссылок**, с прямой пометкой почему.
- **Дата проверяется** — приоритет у даты из выдачи поиска; дату от модели принимаем, только если она реально встречается в тексте страницы. Иначе дата пустая и балл ниже.
- **Подтверждения считает код** — по числу открытых страниц **других изданий** по той же теме.
- **Повторов нет** — адреса прошлых тем исключаются прямо в выдаче поиска, а заголовки сверяются по общим основам слов (порог 0.6). Память — 30 дней, включая темы из раздела «Выпуск».
- **Страницы-витрины отсеиваются** — ленты тегов, рубрики и страницы авторов темой быть не могут.
- **Меньше трёх тем — законный исход.** Если основания не нашлось, раздел честно пишет, какого типа не хватило, и не подставляет вторую тему соседнего типа.

### Два провайдера: кто что делает

Работа разделена не по остаточному принципу, а по способностям.

**Разбор страниц** — механическая задача: прочитать текст, вытащить дословную цитату и факты в JSON. Русский стиль там не важен, зато важен объём: это три вызова из семи. Идёт на **Groq**, у которого бесплатный лимит на порядки больше, чем 20 запросов в сутки у Gemini.

**Написание контента** — голос владельца, русский текст без коучинговых штампов. Идёт на **Gemini**, и только когда его суточная квота кончится, тема уходит на Groq: лучше другой стиль, чем пустой слот.

| Шаг | Очередь |
|---|---|
| Повестка | Gemini Flash Lite (отдельная квота) |
| Отбор оснований | Groq → Gemini |
| Написание | Gemini (2 модели) → Groq |

Замер на одной и той же работе: пачка из четырёх страниц разбирается на Groq за **4–7 секунд**, на Gemini занимала **40–140**. Весь прогон сократился с 335 до 166 секунд.

Модели Groq выбраны не по списку, а по проверке: обе умеют **цитировать дословно**. Это не придирка — код сверяет цитату с текстом страницы и отбрасывает материал, если её там нет. `gpt-oss-20b` на проверке переписала «считают» в «считаются» и обрезала фразу, поэтому в списке её нет.

Пачки через Groq идут **по очереди, а не разом**: лимит там считается в токенах за минуту и общий на ключ, поэтому одновременный запуск его же и пробивает. Скорость это почти не съедает.

### Как добавить ещё провайдера

Groq говорит на протоколе OpenAI, и адаптер в `src/lib/model.ts` написан под протокол, а не под конкретного поставщика. Чтобы добавить Cerebras, Mistral или OpenRouter, нужны строка в `GROQ_MODELS`-подобном списке и ключ в `.env.local` — остальное подхватится ротацией.

Ключи целиком необязательны: без `GROQ_API_KEY` всё работает на одном Gemini, просто медленнее и с более узким дневным лимитом.

### Бюджет прогона

Семь вызовов модели в спокойном случае: 1 (повестка) + 3 (отбор) + 3 (написание). На замерах выходило 13–16: когда у модели кончается квота, пачка или тема уходит на соседнюю, и каждая попытка считается. Вызовы размазаны по семи моделям двух провайдеров с **раздельными лимитами**. Кредитов Tavily — около 18 на прогон. Время — 2,5–3 минуты.

### Про «каждый день автоматически»

Лента собирается **по вашему заходу в новый день**, а не сама по себе в фоне. Локальное приложение не может проснуться в 8 утра, если компьютер выключен или сервер не запущен. Раздел сам видит, что ленты на сегодня нет, и предлагает собрать её одной кнопкой. Настоящий планировщик — отдельная задача поверх этого.

Лента дня хранится в `data/feeds/ГГГГ-ММ-ДД.json`. Повторный запрос на ту же дату, пока прогон идёт, получает 409: две открытые вкладки не должны тратить двойную квоту.

## Как устроен конвейер

`src/lib/pipeline.ts` — пять шагов, каждый отдаёт события в интерфейс через SSE (`/api/generate`):

1. **Ресерч** — модель составляет план из `maxSearches` поисковых запросов, каждый с блоком (мир / Казахстан / СНГ / наука). Запросы выполняет наш код через Tavily **строго по спискам доменов** из `src/lib/sources.ts` (`include_domains_mode: restrict`). Затем модель сводит выдачу в заметки — интернета у неё при этом нет.
2. **Проверка** — модель выбирает до `maxFetches` первоисточников. Наш код открывает их: сначала обычным запросом, а издания, которые режут ботов или рисуют страницу скриптом, — через Tavily `/extract`. Модель сверяет факты по текстам открытых страниц; высокая уверенность допустима только там, где страница открылась.
3. **Тема и три формата** — вызов без поиска: только из проверенных фактов, строго в JSON.
4. **Проверка структуры** — Zod-схема выпуска (`src/lib/schema.ts`); если модель ошиблась в структуре, одна повторная попытка с описанием ошибки.
5. **Сохранение** — `data/editions/ГГГГ-ММ-ДД.json` (при повторной генерации в тот же день — `-2`, `-3`…).

Поиск и открытие страниц выполняет наш код, поэтому `maxSearches` и `maxFetches` — настоящие пределы, а не пожелание в промпте. Сеть и API рвутся регулярно, поэтому каждый внешний вызов обёрнут повторами; при 429 пауза берётся из ответа API.

Промпты собираются из брифа в `src/lib/brief.ts`. Бриф редактируется в интерфейсе (раздел «Бриф») и хранится в `data/settings.json`; пока файла нет, действует `DEFAULT_SETTINGS`.

Рубрика дня недели задаёт угол (понедельник — цифра недели, вторник — платформы, среда — кейс из Казахстана/СНГ, четверг — наука, пятница — спор экспертов, суббота — B2B и первые лица, воскресенье — стратегия). Темы последних 14 выпусков передаются модели как «уже использованные».

## Структура

```
data/
  editions/           выпуски (JSON, по одному на прогон)
  feeds/              ленты дня (JSON, по одному на дату)
  research.json       сохранённые темы и последние исследования
  settings.json       бриф и параметры (создаётся при первом сохранении)
src/
  app/
    page.tsx          серверный вход: читает data/ и рендерит <App/>
    api/generate      POST, SSE-поток событий конвейера выпуска
    api/feed          GET лента за день; POST, SSE-поток сборки ленты
    api/research      POST, SSE-поток исследования произвольной темы
    api/settings      GET/PUT бриф
    api/editions      GET список выпусков
    api/health        GET проверка ключа и модели
  components/         интерфейс (клиентские компоненты, Framer Motion)
  lib/
    schema.ts         Zod-схемы выпуска и настроек, типы событий
    brief.ts          бриф по умолчанию и сборка системных промптов
    sources.ts        списки доменов, которыми ограничен поиск
    search.ts         Tavily: поиск и открытие страниц, всё хождение в интернет
    pipeline.ts       конвейер выпуска (пять шагов, события через SSE)
    feed.ts           лента дня: три темы разных типов × три формата
    research.ts       исследование произвольной темы по запросу
    text-match.ts     сверка цитат и понятий с текстом страницы (общий модуль)
    credibility.ts    балл надёжности: веса зафиксированы в коде
    model.ts          вызовы модели, повторы, ротация по суточным квотам
    steps.ts          описания шагов для панели прогресса
    store.ts          файловое хранилище
    to-text.ts        выпуск → текст для копирования
  preview/entry.tsx   вход статического превью (без сервера)
scripts/build-preview.mjs   собирает preview/index.html — интерфейс одним файлом
```

## Модель

По умолчанию `gemini-3.5-flash`. Сменить можно в разделе «Бриф» без перезапуска.

**Бесплатный тариф Gemini считает лимит отдельно по каждой модели, и у флагманских он всего 20 запросов в сутки.** Один прогон тратит 5–6 вызовов — примерно 3–4 выпуска в день на одной модели. Когда квота кончилась, конвейер прямо об этом пишет и предлагает сменить модель: у соседней запас свой. Есть и минутный лимит, он проходит сам за несколько секунд, повторы это учитывают. Расход — на [ai.dev/rate-limit](https://ai.dev/rate-limit).

Tavily на бесплатном тарифе даёт 1 000 кредитов в месяц: поиск `advanced` — 2 кредита, `/extract` — около 1 кредита за несколько страниц. Прогон обходится примерно в 40 кредитов, то есть **около 25 выпусков в месяц**. Фактический расход пишется в лог конвейера в конце прогона.

Списки разрешённых доменов лежат в `src/lib/sources.ts` и в настройках (`sourceDomains`); правка через интерфейс пока не сделана.

## Что дальше

- **Доставка**: после события `done` в `/api/generate` отправить `editionToText(edition)` в Telegram или письмом.
- **Расписание**: любой планировщик, который умеет `POST http://localhost:3000/api/generate` (cron, n8n, GitHub Actions на сервере).
- **Другая модель**: заменить три вызова в `pipeline.ts` на другого провайдера с веб-поиском; интерфейс и схема выпуска не меняются.
- **База вместо файлов**: `store.ts` — единственное место, где читается и пишется `data/`.
- **Голос**: правится в поле «Голос и стиль» брифа; примеры своих постов можно добавить туда же.
